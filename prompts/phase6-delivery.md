# Phase 6 — Delivery

Three artifacts: two `.docx` per batch (the copy and the infos) and one upload sheet for the round.

## The two `.docx` per batch

One pair per cell, **not per image** — the copy is the same across the three variations.

```
AA BRAND-SKU T101-B1-A/AA BRAND-SKU T101-B1-A.docx   <- copy only, in the cell folder next to the 3 images
infos/AA BRAND-SKU T101-B1-A INFOS.docx              <- angle, level and the prompts of the 3 images
```

The source `.md` files stay in `drafts/`, references in `support/`.

### Formatting (house document standard)

Arial 12pt, 1.5 line spacing, black, headings in ALL CAPS and bold, margins 3-3-2-2 cm. Generated by the script, not by hand. One command builds both documents:

```bash
python "$HOME/.claude/skills/longform-builder/scripts/build_batch_docx.py" \
    --draft drafts/B1-A.md          # writes to AA BRAND-SKU T101-B1-A/
```

### The copy document

**Literally only the copy.** No title, no angle, no avatars, no headline, no description, no CTA, no file list. It is the file that goes to whoever uploads the ad. Headline, description and CTA are not in any docx: they live only in `upload.csv`.

1. **Primary text**, no heading, paragraph by paragraph
2. **FIRST THREE LINES (n CHARACTERS)**, all caps and bold, followed by the three lines

### The INFOS document

In this order:

1. **Document name** (centered)
2. **ANGLE** — the angle name and its explanation
3. **AWARENESS LEVEL** — only the label, no explanation: `Problem aware (A)`, `Solution aware (B)` or `Hidden cause (C)`
4. **IMAGE PROMPTS** — the locked scene, then for each image the label, the filename and the **full prompt**, read from `image-brief.md`. If an image is regenerated, rebuild the INFOS so the prompt still matches the image.

## The upload sheet

`upload.csv`, one row per ad (45 in a 5 x 3 x 3 round), in the format the media buyer uploads:

| Column | Content |
|---|---|
| `campaign` | name of the test campaign |
| `ad_set` | one per batch (the ad set is what receives the $100) |
| `ad` | `AA BRAND-SKU T101-B1-A1` |
| `image` | filename |
| `primary_text` | the long-form copy |
| `headline` | link headline |
| `description` | link description |
| `cta` | button |
| `destination` | destination URL |
| `angle` / `level` / `variation` / `ethnicity` | the dimensions, for the later read |

The last four columns exist so `creative-intel` can read the round without rebuilding the classification. **That is what closes the loop**: the round is born already classified.

```bash
python "$HOME/.claude/skills/longform-builder/scripts/build_batch_docx.py" \
    --sheet --test T101 --product BRAND-SKU --destination "https://..." --out upload.csv
```

## Final logging

1. Update `tracking/batches.json`: everything to `delivered`
2. Update `progress.md`
3. **Add every angle and hook to the product's `kill-list.md`**, with the matching file, so the next round does not repeat it
4. Log one line in the product's `progress.md` pointing at the test folder

## What to tell the user at closing

Two things, always:

- **The reading floor.** No conclusions before $850.85 per cell or 10 conversions. A cell crosses that floor in a few days; before it does, any read is noise.
- **Do not promote on CTR.** On this account, hook rate is not monotonic. High CTR on the image is not a winner signal. The signal is sales.
